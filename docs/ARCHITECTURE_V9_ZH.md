# weekly21 v9 端到端运行逻辑

## A. 检索与候选形成

1. 根据北京时间星期选择当天 3 个 profile；手工运行可选择单个、多个或全部 21 个。
2. 每个 profile 使用 5 个高区分度核心检索概念。
3. PubMed、Europe PMC、Crossref、Semantic Scholar、OpenAlex、bioRxiv/medRxiv 分别使用适配器检索元数据和 API 摘要。
4. Google/Bing RSS、GDELT、ReliefWeb 和 WHO 形成新闻候选。
5. Python 对 100% 候选做身份、限定缩写、上下文、排除实体和词频检查；仅边界项进入 LLM。
6. DOI、PMID、规范化标题、作者年份和 URL/标题相似度去重，并合并来源、概念、摘要和直接 URL。

## B. 展示候选与补位

1. 相关性通过后按来源收敛度、文章类型、热点、时间、摘要完整度和来源权威性排序。
2. 文献、新闻各保留目标 50 条加 30 条补位池，最多 80 条进入昂贵内容处理。
3. 文献补摘要/合法开放全文；新闻解析聚合器跳转、canonical、JSON-LD、脚本内 URL 和直接发布者 URL。
4. 新闻全文不可用时，只有通过长度、句子数、标题相似度和目标病原校验的实质性转载摘要，才以 `syndicated_summary` 降级保留。
5. 内容处理、分析和翻译失败不会立即缩小输出；最终从整个就绪池重新排序，取 Top 50。

## C. 单篇分析

研究论文七要素：背景问题、设计对象、方法、结果、解释创新、科研/公卫意义、局限与证据强度。

综述五要素：范围问题、证据方法、共识结论、争议缺口、科研实践启示。

新闻五要素：时间、地点对象、事件、规模风险、应对状态与不确定性。

每个输入证据句带有 rhetorical role。模型返回字段引用的证据角色必须与字段相符；不相符则重试或使用角色对齐的 Python 回退。

## D. 翻译和补位

1. deep-translator Google；
2. Python Google 兼容入口；
3. MyMemory；
4. 批量 LLM；
5. 对批量结果遗漏字段逐字段重新调用完整翻译链；
6. 校验中文比例、数字、术语、非空和占位符；
7. 从翻译就绪池重新排序，最终选择 50 条。

## E. 分离式综合汇总

文献与新闻分别选择 15～25 条。文献汇总使用标题、作者、期刊、日期、原始摘要、中文摘要、单篇结构化要素、质量分和证据等级；新闻汇总仅使用正文或可核验实质摘要。

中文汇总强制：中文比例达标、不得出现省略号、不得出现未完成句、不得包含翻译占位符、每个重点结论引用真实 paper_id/news_id。失败后使用中文字段构建确定性完整句回退，不以英文分析填充中文区块。

## F. 发布

生成 profile 页面、组合门户、RSS、审计 JSON 和 `wechat-package/v2`；提交到 `intelligence-data`；Pages 部署；可选 `repository_dispatch` 私有仓；本地 Runner 校验精确提交 SHA 后创建公众号草稿，不自动群发。
