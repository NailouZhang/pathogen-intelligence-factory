# v7 LLM 与 Token 策略

## 1. 三种不同任务

### 相关性边界复核

只处理 Python 无法可靠判定的候选，使用紧凑证据包，批量返回 A/C/B/N/U。

### 最终单条解读

只处理 Top 50 文献和 Top 50 新闻。文献输出背景、方法、结果、贡献、局限；综述输出背景、主要方向、研究现状、不足、后续研究；新闻输出时间、地点、事件、影响、状态。

### 双语翻译与综合概览

只处理最终展示集合，并使用内容哈希缓存避免相同条目重复调用。

## 2. Token 控制不依赖篇数截断

相关性复核不设置“最多复核多少篇”。Python 先抽取相关句子并构建紧凑 JSON，程序按 `PIF_LLM_COMPACT_BATCH_TOKENS` 打包，直到边界队列为空。只有 U 类升级到 `PIF_LLM_ESCALATION_BATCH_TOKENS` 的更完整证据。

## 3. 回退

- Gemini 优先；
- Groq 作为文本回退；
- 每个供应商默认只尝试一个模型；
- 模型失败时 Python 确定性规则继续执行；
- 失败和回退方式写入 `relevance_review.json`。
